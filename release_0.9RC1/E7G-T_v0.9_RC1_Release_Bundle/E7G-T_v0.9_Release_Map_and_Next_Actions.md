## 3. Layer Separation Rule

The same idea may appear in different layers, but each layer must speak differently.

| Layer | Voice | Purpose |
|---|---|---|
| Foundations | rigorous, explanatory, conceptual | Explain why the framework exists. |
| Kernel | compact, normative, reference-style | Define the operational rules. |
| Reference-backed kernel | careful, public-facing | Anchor terminology near established fields. |
| Application Atlas | structured, testable, domain-specific | Show how the kernel works in one domain. |
| Proof-of-Path | formal-methods/accountability | Track path, obligations, checks, and proof status. |
| Practical Guide | accessible, commercial, reader-friendly | Teach ordinary users how to apply the method. |

Rule:

Do not let the practical guide become too technical.

Do not let the kernel become too explanatory.

Do not let the atlas become speculative.

Do not let the foundations become a marketing text.
