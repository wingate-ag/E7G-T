# Migration from E7G-T v0.9 RC1 to v0.10-UC1

## Status

E7G-T v0.9 RC1 is historical. It remains useful for tracing the development of the extensional–projective route, but it is no longer the active project definition.

## Conceptual migration

| v0.9 concept | v0.10 treatment |
| --- | --- |
| Context, purpose, and D7 often blended | Semantic context, inquiry, and optional D7 role are distinct |
| One operational boundary | Model, admissibility, phase, and bridge boundaries are distinguished |
| Transform as a broad arrow | Every material arrow receives a typed change kind |
| Projection review ends with preservation/loss and reconstruction status | Projection review may continue into phase-candidate analysis |
| Invariant under transformation | Distinguished from a phase-defining invariant or protected condition |
| Temporal regime as modelling posture | Kept, but separated from transition-derived temporal motifs |
| OneLine / MiniCard / FullCard | Migrated to E7-Line / E7-Check / E7-Analysis with route modules |
| “Operational” as general posture | Operational readiness may itself be a phase-classification aspect |

## Artifact migration

The old top-level documents should not be edited in place as if only terminology changed. Each application must be re-authored around a phase question.

### AI output

Old emphasis:

> The AI answer is not the source.

Unified emphasis:

> Which admitted source states remain compatible with the answer, and do they all support the same reliance phase?

### Translation

Old emphasis:

> What meaning and documentary invariants were preserved or lost?

Unified emphasis:

> Which target-language differences remain operationally equivalent, and which edit changes legal force, documentary identity, usability, or evidential posture?

### Dashboard

Old emphasis:

> The chart is not the business.

Unified emphasis:

> Does the visible metric state uniquely determine the operational phase, or can healthy and unhealthy source configurations project the same dashboard state?

### Proof path

Old emphasis:

> The proof script is not the proof object.

Unified emphasis:

> Which proof-state configurations count as equivalent for the current obligation, and does the visible interface state support the claimed proof-readiness phase?

## Repository migration rule

- `specs/` contains current normative candidates.
- `docs/` contains current explanations, applications, worksheets, and pilots.
- `release_0.9RC1/` remains an immutable historical release.
- old root-level v0.9 artifacts are deprecated and should not be linked as active documentation.

## Compatibility posture

A v0.9 analysis can be imported as an extensional–projective module when it states enough of the following:

- entity;
- context;
- boundary;
- operation;
- preservation/loss;
- reconstruction status;
- admissible use;
- stop condition.

To become a v0.10 combined analysis it must additionally state:

- inquiry;
- admitted configurations;
- phase criterion;
- tolerated differences;
- phase-defining conditions;
- phase-candidate or phase-relation result;
- classification support;
- boundary and next-move status.
