# E7G-T v0.10 Architecture

## 1. Shared constitutional core

Every conforming analysis begins with:

- modelled entity;
- semantic context;
- inquiry;
- admitted configuration description;
- model boundary;
- admissibility conditions;
- evidence/support posture;
- admissible use;
- stop or source-return condition.

This core prevents D-order labels, phase labels, diagrams, equations, or formal-looking schemas from silently replacing the object being modelled.

## 2. Extensional–projective route

This route retains the practical moves inherited from v0.9:

```text
Place → Bound → Incide → Extend → Slice → View/Project
→ Preserve/Lose → Transform → Reconstruct → Bridge/Stop
```

Its principal outputs are construction accounts, projection accounts, preservation/loss ledgers, reconstruction fibres, transformation-invariant statements, and bridge limits.

## 3. Operational-phase route

An operational phase is an inquiry-relative equivalence class of admitted configuration descriptions.

The route requires:

- a pinned phase criterion;
- tolerated differences;
- protected relations, invariants, behaviours, interfaces, or action signatures;
- support for the classification;
- typed changes and transitions;
- phase-boundary status;
- representative and path checks where relevant.

## 4. Combined route

The combined route governs the case where a view is used to classify operational status.

```text
source/configuration
      ↓ viewing or projection
visible view
      ↓ reconstruction fibre
admitted source candidates
      ↓ phase quotient under Q
phase candidates
      ↓
classify | narrow | abstain | source return | repair | stop
```

### Phase-candidate rule

```text
PhaseCandidates_Q(v) = { [Γ]_Q | Γ ∈ Rec_π(v) }
```

A view is phase-sufficient only when the relevant reconstruction fibre is phase-stable under the pinned criterion and the support basis is adequate for the intended use.

## 5. Boundary stack

The word “boundary” is split into distinct functions:

- **Model boundary:** what is included in the configuration description.
- **Admissibility boundary:** which configurations and changes are admitted for comparison.
- **Phase boundary:** where phase equivalence fails under the criterion.
- **Bridge boundary:** where a claim changes domain, substrate, authority, or empirical posture.

Crossing one boundary does not imply crossing the others.

## 6. Typed-change discipline

A visible difference must not automatically be called a transformation. The unified kernel distinguishes, among others:

- world transformation;
- configuration revision;
- viewing;
- order projection;
- retargeting;
- reframing;
- classification;
- observation update;
- work occurrence;
- dynamics-model update.

A reclassification does not by itself change the world. A new view does not by itself change the source. A document revision may change a configuration description without changing the represented entity.

## 7. D-orders and temporal profiles

D0–D7 remain optional modelling roles and compatibility lenses. They do not replace semantic context, inquiry, phase criterion, or domain ontology.

Declared temporal regimes are separated from temporal motifs derived from transition structure. A label such as cyclic-time does not prove the existence of an admitted transition loop.

## 8. Practical escalation

```text
E7-Line → E7-Check → E7-Analysis → FormalisationCard
```

Escalation is required when the basis is disputed, the result is reused, the decision is consequential, contexts are crossed, representative dependence is suspected, or machine checking is required.

Formalisation is not automatically a higher-quality answer. It is justified only when it changes validation, implementation, reuse, or reliance.
